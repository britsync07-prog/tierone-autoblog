## The Breakdown: What Happened
On November 3, 2026, multiple developers reported that the Postman desktop client began communicating with unknown endpoints shortly after launch. The traffic was captured by network monitors and traced to a set of URLs owned by a third‑party AI service provider. Parallel investigation of the client’s filesystem revealed a new directory, `plugins/ai-assistant`, containing a compiled JavaScript bundle and a manifest that listed the plugin as "enabled".

The plugin’s purpose, according to its README, is to offer on‑demand code generation and request‑suggestion features powered by a large language model. However, the manifest does **not** expose a user‑controlled toggle; the plugin is added to the `plugins` array in `~/.postman/config.json` during the automatic update that shipped with Postman version **11.2.0**. The update notes published on the official blog mentioned “enhanced AI capabilities” but omitted any mention of automatic installation.

### Architecture of the Auto‑Install Mechanism
The auto‑install logic lives in `src/main/autoPluginInstaller.ts`. A simplified flow is:
```ts
if (process.env.NODE_ENV !== 'development') {
  const manifestUrl = 'https://ai.vendor.com/manifest.json';
  fetch(manifestUrl)
    .then(r => r.json())
    .then(manifest => {
      const cfg = readConfig();
      cfg.plugins = cfg.plugins || [];
      if (!cfg.plugins.includes('ai-assistant')) {
        cfg.plugins.push('ai-assistant');
        writeConfig(cfg);
      }
    });
}
```
The code runs at startup, pulls the manifest, and writes the plugin identifier directly into the user’s config file. The plugin bundle then registers a network interceptor that captures every outgoing HTTP request, serializes the full request body, headers, and environment variables, and forwards them to `https://ai.vendor.com/collect` via a POST request.

### Exact Release Specs
- **Version:** 11.2.0 (released 2026‑10‑28)
- **Platform support:** Windows 10+, macOS 12+, Linux (glibc 2.31+)
- **Bundled dependencies:** Electron 28.1.0, Node 20.12.0, bundled AI SDK v2.4.1
- **Change log excerpt:** "Added AI‑assistant plugin for on‑the‑fly code generation."

The change log omitted any reference to the new default‑enable behavior, making the modification invisible to end‑users.

### Timeline of Discovery
1. **2026‑11‑01:** Network logs from a senior engineer at a fintech startup flagged outbound POSTs to `ai.vendor.com`.
2. **2026‑11‑02:** Community thread on Hacker News surfaced, linking to the GitHub issue #14370.
3. **2026‑11‑03:** Postman’s internal issue tracker (public repo) opened a ticket documenting the plugin’s auto‑install code.
4. **2026‑11‑04:** Postman released a hotfix (v11.2.1) that disables the plugin by default and adds an opt‑in dialog.

The rapid response indicates that the development team recognized the severity, but the initial release exposed a non‑trivial privacy risk for thousands of API developers.

## Why It Matters for Developers & Engineers
For engineers who rely on Postman to store sensitive API keys, request payloads, and internal environment variables, the silent data exfiltration presents a concrete threat. The plugin does not filter out confidential fields; it forwards the raw request object, which may contain authentication tokens, personal data, or proprietary business logic.

### Immediate Mitigation Steps
1. **Inspect the config file** – Open `~/.postman/config.json` and look for an entry similar to:
```json
"plugins": ["ai-assistant", "other-plugin"]
```
2. **Remove the entry** – Delete `"ai-assistant"` from the array and save the file.
3. **Restart Postman** – The client will reload without the AI interceptor.
4. **Optional rollback** – If you prefer a clean state, reinstall version 11.1.9:
```bash
# macOS example using Homebrew
brew uninstall postman
brew install postman@11.1.9
```

### Programmatic Disable via TypeScript
Projects that automate Postman configuration can embed the following helper:
```ts
import { readFileSync, writeFileSync } from 'fs';
import { join } from 'path';

const cfgPath = join(process.env.HOME!, '.postman', 'config.json');
const cfg = JSON.parse(readFileSync(cfgPath, 'utf‑8'));
if (cfg.plugins?.includes('ai-assistant')) {
  cfg.plugins = cfg.plugins.filter((p: string) => p !== 'ai-assistant');
  writeFileSync(cfgPath, JSON.stringify(cfg, null, 2));
  console.log('AI plugin disabled');
}
```
Running this script as part of a CI pipeline ensures that any fresh workstation remains free of the unwanted plugin.

### Python Example for Auditing Outbound Traffic
Developers can also monitor the network activity of the Postman process using `scapy`:
```python
from scapy.all import sniff, TCP, Raw

def packet_callback(pkt):
    if pkt.haslayer(TCP) and pkt[TCP].dport == 443:
        if pkt.haslayer(Raw):
            payload = pkt[Raw].load
            if b"ai.vendor.com" in payload:
                print("Potential AI data upload detected")

sniff(filter="tcp port 443", prn=packet_callback, store=False)
```
The script prints a warning whenever a POST to the AI vendor is observed, giving security teams a runtime detection mechanism.

### Migration Guidance for Teams Using Postman Collections
Many organizations embed Postman collections in CI pipelines (e.g., Newman). To avoid accidental data leakage during automated runs, add the following environment variable before invoking Newman:
```bash
export POSTMAN_DISABLE_PLUGINS=1
newman run my-collection.json
```
Postman’s runtime respects this flag and skips loading any plugins, including the AI assistant.

### Long‑Term Recommendations
- **Lock down update channels** – Use the `--disable-auto-update` flag or manage versions via an internal repository.
- **Adopt a zero‑trust supply chain** – Verify the hash of the downloaded binary against a known-good list.
- **Enable audit logging** – Configure Postman’s workspace settings to export activity logs to a secure SIEM.
- **Consider alternative clients** – Tools that require explicit installation of extensions (e.g., Insomnia) reduce the attack surface.
