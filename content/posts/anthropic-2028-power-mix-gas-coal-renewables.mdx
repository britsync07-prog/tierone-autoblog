## The Breakdown: What Happened

On 16 November 2026, a detailed analysis published by the Better Data Center Project was shared on Hacker News. The report examined Anthropic’s power‑purchase strategy for its next‑generation AI clusters, focusing on the “Bring‑Your‑Own‑Power” (BYOP) contracts that the company signed with regional utilities. The key numbers are:

* **87 %** of the projected 2028 electricity consumption will be supplied by **natural‑gas‑fired generation**.
* **11 %** will come from **coal‑based plants**.
* The remaining **~2 %** will be sourced from **wind, solar, and hydro**.

The analysis breaks down the mix by region, showing that the bulk of Anthropic’s compute will sit in the U.S. Midwest and Southeast, both of which have historically high fossil‑fuel shares in their grid. The report also notes that Anthropic’s BYOP contracts lock in fixed tariffs for the next twelve years, a move designed to stabilize operating expenses as AI compute demand continues to climb.

### Architecture and Capacity Assumptions

Anthropic’s upcoming models—Claude 3.5 and Claude‑Next—are expected to run on custom‑built GPU clusters that consume **approximately 250 MW** of continuous power. The BYOP contracts allocate **217 MW** to natural‑gas turbines, **27 MW** to coal plants, and **6 MW** to renewable generators. The report cites internal capacity‑planning documents that project a **30 % year‑over‑year growth** in compute demand from 2025 to 2028, driven by expanded API usage and new enterprise integrations.

### Verification Methodology

The Better Data Center Project used a combination of public utility filings, satellite‑derived night‑light data, and Anthropic’s disclosed energy‑budget spreadsheets. Cross‑checking with the U.S. Energy Information Administration (EIA) confirmed that the regional generation mixes reported by the project match the official grid averages within a 2‑percentage‑point margin.

### Why the Numbers Matter

Natural gas, while cleaner than coal on a per‑megawatt‑hour basis, still emits roughly **0.45 kg CO₂/kWh**, whereas coal emits **0.95 kg CO₂/kWh**. At 244 MW average load, Anthropic’s projected 2028 emissions amount to **≈1.2 Mt CO₂ per year**, a figure comparable to the annual emissions of a mid‑size city. The limited renewable share means that even aggressive efficiency gains would have a modest impact on total carbon output unless the power source itself changes.

## Why It Matters for Developers & Engineers

### Energy‑Aware Scheduling in Practice

Developers building on Anthropic’s API can incorporate carbon‑aware scheduling to shift non‑urgent inference calls to periods when the grid’s carbon intensity dips. The following Python snippet demonstrates how to query the **Carbon Intensity API** (provided by the Electricity Map project) and delay a request until the intensity falls below a threshold:

```python
import time, requests
from datetime import datetime, timedelta

API_URL = "https://api.electricitymap.org/v3/carbon-intensity/latest?zone=US-MIDWEST"
THRESHOLD = 400  # gCO₂/kWh

def get_current_intensity():
    resp = requests.get(API_URL)
    data = resp.json()
    return data["carbonIntensity"]

def schedule_request(payload, max_delay=3600):
    start = datetime.utcnow()
    while (datetime.utcnow() - start).seconds < max_delay:
        intensity = get_current_intensity()
        if intensity &lt;= THRESHOLD:
            break
        time.sleep(300)  # wait 5 minutes before re‑checking
    # Call Anthropic API after low‑intensity window
    response = requests.post(
        "https://api.anthropic.com/v1/complete",
        json=payload,
        headers={"x-api-key": "YOUR_KEY"}
    )
    return response.json()
```

The same logic can be expressed in TypeScript for serverless functions:

```typescript
import fetch from "node-fetch";

const API_URL = "https://api.electricitymap.org/v3/carbon-intensity/latest?zone=US-MIDWEST";
const THRESHOLD = 400; // gCO₂/kWh

async function getCurrentIntensity(): Promise<number> {
  const res = await fetch(API_URL);
  const data = await res.json();
  return data.carbonIntensity;
}

export async function scheduleAnthropic(payload: any, maxDelay = 3600_000) {
  const start = Date.now();
  while (Date.now() - start < maxDelay) {
    const intensity = await getCurrentIntensity();
    if (intensity &lt;= THRESHOLD) break;
    await new Promise(r => setTimeout(r, 300_000)); // 5 min
  }
  const resp = await fetch("https://api.anthropic.com/v1/complete", {
    method: "POST",
    headers: { "Content-Type": "application/json", "x-api-key": process.env.ANTHROPIC_KEY! },
    body: JSON.stringify(payload),
  });
  return resp.json();
}
```

### Migration Path to Greener Cloud Regions

Anthropic offers a **region selector** in its API dashboard. By moving workloads from the default US‑Midwest endpoint to the **US‑Pacific (Oregon) region**, developers can tap into a grid where renewables contribute >30 % of generation. The migration steps are straightforward:

1. **Identify** the region flag in your SDK configuration (`region: "us-west"`).
2. **Update** DNS entries or endpoint URLs to `api.anthropic.com/v1/complete?region=us-west`.
3. **Run** a performance benchmark to verify latency remains within acceptable bounds (typically &lt; 50 ms added).
4. **Monitor** the new region’s carbon intensity via the same API used above.

### Sample Migration Script (Bash)

```bash
#!/usr/bin/env bash
# Switch Anthropic API region to a greener zone
CURRENT_KEY=${ANTRHOPIC_API_KEY}
NEW_REGION="us-west"
ENDPOINT="https://api.anthropic.com/v1/complete?region=${NEW_REGION}"

cat <<EOF > anthropic_config.json
{
  "apiKey": "${CURRENT_KEY}",
  "endpoint": "${ENDPOINT}"
}
EOF

echo "Configuration updated to use region ${NEW_REGION}."
```

### Impact on Cost and Performance

The BYOP contracts lock in a **fixed price of $0.045/kWh** for natural‑gas power, compared with a market‑average of $0.053/kWh for renewable‑heavy grids. Switching to a greener region can raise electricity cost by up to **15 %**, but the carbon benefit is roughly a **70 % reduction** in per‑request emissions. Engineers need to weigh the trade‑off based on SLA requirements and corporate sustainability targets.
