<plan_context>
## Phase Boundary Context
Phase 5 guarantees that no corrupted, placeholder-ridden, or broken article remains on production.
Plan 05-03 builds the post-publish live-URL verification suite and automated rollback engine (AUTO-02):
1. **Exponential Backoff Polling (D-04):** Awaits Vercel edge deployment propagation for up to 3 minutes.
2. **Multi-Point HTML Verification (D-05):** Verifies HTTP 200, valid Article & Breadcrumb JSON-LD, zero placeholder/hallucination tokens, and 100% healthy internal links.
3. **Automated Git Revert Rollback (D-06):** On any failure, the post is physically quarantined, incident report logged, and an automated git unpublish commit is pushed to `master` to redeploy clean state instantly.

## Decisions Handled
- **D-04:** Post-Deploy Polling with Exponential Backoff (intervals up to 180s total timeout).
- **D-05:** Multi-Point Verification Suite (HTTP 200, Article & Breadcrumb JSON-LD, banned placeholder scan, internal link 200 OK checks).
- **D-06:** Automated Git Revert Rollback (moves to `content/quarantine/`, incident report `{id}-live-fail-report.json`, registry stage `'quarantined'`, git commit `[auto-unpublish] <slug>` pushed to `master`).
</plan_context>

<task id="05-03-01" wave="3">
<description>
Implement multi-point live URL verifier in `lib/pipeline/publish/verifier.ts` verifying HTTP status, JSON-LD schemas, placeholder markers, and link health.
</description>
<action>
1. Create `lib/pipeline/publish/verifier.ts`:
   - Export interfaces: `VerificationCheckResult`, `LiveVerificationReport`.
   - Function `pollUntilLive(url: string, timeoutMs?: number, customFetch?: typeof fetch): Promise<{ ok: boolean; status: number; html?: string; error?: string }>`:
     - Uses intervals `[15000, 20000, 30000, 30000, 40000, 45000]` (default max ~180s).
     - Loops `GET` requests with `User-Agent: TierOne-LiveVerifier/1.0`.
     - Returns `{ ok: true, status: 200, html }` once HTTP 200 with `text/html` is received.
     - Times out with `{ ok: false, status, error: 'Deployment polling timed out after ...ms' }`.
   - Function `extractJsonLd(html: string): any[]`:
     - Extracts all `<script type="application/ld+json">...</script>` contents.
     - Parses JSON safely (skipping corrupted scripts).
   - Function `validateJsonLd(jsonObjects: any[]): { articleValid: boolean; breadcrumbValid: boolean; errors: string[] }`:
     - Article schema: checks for `@type === 'Article'` (or in `@graph`), valid `headline` (length >= 10), author `@type === 'Person'` with name `'Musfiqur Rahman Saimon'`, and valid `datePublished`/`dateModified`.
     - Breadcrumb schema: checks for `@type === 'BreadcrumbList'` and `itemListElement` array length >= 3.
   - Function `scanPlaceholders(html: string): { clean: boolean; matches: string[] }`:
     - Strips `<script>`, `<style>`, and HTML comments from raw HTML.
     - Scans text against `BANNED_PATTERNS`:
       - `/\[TODO\]/i`
       - `/\[Insert\s+[^\]]+\]/i`
       - `/\[TBD\]/i`
       - `/lorem\s+ipsum/i`
       - `/\bundefined\b/`
       - `/\bNaN\b/`
       - `/<!--\s*TODO\s*-->/i`
       - `/\b(?:FIXME|PLACEHOLDER)\b/i`
     - Returns `{ clean: matches.length === 0, matches }`.
   - Function `verifyLiveUrl(url: string, options?: { timeoutMs?: number; probeLinks?: boolean; customFetch?: typeof fetch }): Promise<LiveVerificationReport>`:
     - Runs `pollUntilLive`.
     - Validates JSON-LD.
     - Runs `scanPlaceholders`.
     - If `probeLinks !== false`, extracts internal links (`href="/blog/*"`, `href="/<silo>"` etc.) and probes via `HEAD` or `GET` ensuring status 200.
     - Returns comprehensive `LiveVerificationReport` with `passed: boolean`, individual check statuses, and diagnostics.
2. Create unit tests in `tests/verify-live-url.test.ts` testing:
   - Polling retry backoff logic with mock fetch.
   - JSON-LD extraction and validation (valid Article + Breadcrumb passes; missing author or short headline fails).
   - Placeholder detection with clean vs dirty HTML samples.
</action>

<threat_model>
### Threat Ref T-05-05: Corrupted, Incomplete, or Hallucinated Content on Live Site
- **Threat:** A post containing model hallucinations, unresolved placeholders (`[TODO]`, `[Insert image]`, `undefined`), or invalid JSON-LD schema deploys to edge production, harming user trust and risking Google thin-content / spam-policy penalties.
- **Mitigation:** The live-URL verifier scans the real production HTML returned by Vercel. It strictly validates Article and BreadcrumbList JSON-LD structure and searches the body for any banned token. Any detection triggers `executeAutomatedRollback`, unpublishing the post in under 2 minutes.
- **Verification:** Unit test `tests/verify-live-url.test.ts` supplies HTML containing `[TODO]` and invalid schema, asserting verification failure and rollback execution.

### Threat Ref T-05-06: Dead Internal Links & 404 Crawl Waste
- **Threat:** A newly published post links to non-existent blog posts, missing silo hubs, or deleted author pages, bleeding crawl budget and creating 404 crawl errors in Search Console.
- **Mitigation:** The verifier extracts all internal links from the rendered DOM and executes HTTP HEAD/GET probes against every unique internal target. Any non-200 status causes verification to fail, aborting indexing and unpublishing the page.
- **Verification:** Unit test `tests/verify-live-url.test.ts` mocks a page with a 404 internal link, confirming it fails verification and prevents IndexNow/GSC submission.
</threat_model>
