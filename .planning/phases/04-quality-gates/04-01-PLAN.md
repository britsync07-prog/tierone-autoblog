## Phase Boundary Context
Phase 4 implements fail-closed quality gates. Plan 04-01 lays the foundational infrastructure for physical quarantine isolation and the $K=3$ consecutive failure circuit-breaker before individual gate checkers are wired.

## Decisions Handled
- D-01: Physical Isolation (`content/posts/` $\rightarrow$ `content/quarantine/{id}.mdx` + `{id}-report.json`)
- D-02: Dedicated Registry Stage `'quarantined'` in `lib/pipeline/types.ts` & `registry.ts`
- D-03: CLI tools (`quarantine:list`, `quarantine:view <id>`) and `content/quarantine/SUMMARY.md`
- D-10: $K = 3$ Consecutive Failure Circuit-Breaker
- D-11: Halt Lockfile (`content/keywords/pipeline-state.json`) + CLI Resume (`npm run pipeline:resume`)
- D-12: Multi-Channel Alerting (stderr banner, `ALERT.md`, optional `ALERT_WEBHOOK_URL`)
</plan_context>

<task id="04-01-03" wave="1">
<description>
Implement circuit-breaker state machine and multi-channel alert engine in `lib/pipeline/qa/circuit-breaker.ts`.
</description>
<actions>
1. Create `lib/pipeline/qa/circuit-breaker.ts`:
   - Interface `PipelineState`:
     ```ts
     export interface PipelineState {
       paused: boolean;
       pausedAt?: string;
       consecutiveFailures: number;
       failureHistory: Array<{ id: string; failedRule: string; timestamp: string }>;
       reason?: string;
     }
     ```
   - Functions:
     - `readPipelineState(keywordsDir?: string): PipelineState` (defaults to `{ paused: false, consecutiveFailures: 0, failureHistory: [] }` if missing).
     - `recordQaSuccess(keywordsDir?: string): void` (resets `consecutiveFailures` to 0).
     - `recordQaFailure(failure: { id: string; failedRule: string }, options?: { keywordsDir?: string; quarantineDir?: string; maxConsecutive?: number }): boolean`
       - Increments `consecutiveFailures`. Appends to `failureHistory` (keeps last 10).
       - If `consecutiveFailures >= maxConsecutive` (default 3):
         - Sets `paused = true`.
         - Writes `content/quarantine/ALERT.md` with headline, details, and resume instructions.
         - Emits bright ANSI red banner to `console.error`.
         - Dispatches optional webhook if `process.env.ALERT_WEBHOOK_URL` is configured.
         - Returns `true` (tripped).
       - Returns `false`.
     - `resetCircuitBreaker(keywordsDir?: string, quarantineDir?: string): void`:
       - Sets `paused = false`, `consecutiveFailures = 0`. Clears or updates `ALERT.md`.
2. In `lib/pipeline/run.ts`:
   - Add preflight check at beginning of `runPipeline`:
     ```ts
     const state = readPipelineState(registryDir);
     if (state.paused) {
       console.error(`FAIL: Pipeline is PAUSED due to ${state.consecutiveFailures} consecutive QA failures.`);
       console.error(`See content/quarantine/ALERT.md for details. Run 'npm run pipeline:resume' to reset.`);
       return 1;
     }
     ```
</actions>
<verification>
Create unit test `tests/qa-circuit-breaker.test.ts` testing 1 failure, 2 failures, 3rd failure tripping pause + creating `ALERT.md`, and `resetCircuitBreaker` recovering.
</verification>
</task>
