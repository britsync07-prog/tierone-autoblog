## Phase Boundary Context
Phase 6 delivers long-term compounding and search authority preservation.
Plan 06-03 implements data-driven 301 redirect consolidation and clean post retirement (GROW-02):
1. **Dynamic 301 Redirect Registry (`content/redirects.json`)**: Machine-readable redirect rules dynamically evaluated by Next.js App Router in `next.config.mjs`.
2. **Redirect Hygiene & Loop Prevention**: Validates redirect pairs to eliminate circular loops and multi-hop chains before runtime activation.
3. **Physical MDX Quarantine & Registry Synchronization**: When an article is superseded or merged, its `.mdx` file is physically relocated to `content/quarantine/{slug}.mdx` and its keyword registry entry transitioned to `'quarantined'`, preventing duplicate builds and index pollution.
4. **Automated Sitemap Pruning**: Because `@content-collections` processes only `content/posts/*.mdx`, physical quarantine automatically purges retired URLs from `sitemap.xml`, allowing search engines to follow the 301 redirect without encountering soft-404s.

## Decisions Handled
- **D-06:** Data-Driven 301 Redirect Registry (`content/redirects.json`, dynamic `next.config.mjs` integration, physical quarantine to `content/quarantine/`, registry stage update to `'quarantined'`).
</plan_context>

1. Create initial `content/redirects.json`:
   - Initialize as a clean JSON array `[]` (or with an illustrative example schema).
2. Create `lib/pipeline/redirects/registry.ts`:
   - Export interface `RedirectEntry`:
     ```typescript
     export interface RedirectEntry {
       source: string;       // e.g. "/blog/chatgpt-vs-claude-2024"
       destination: string;  // e.g. "/blog/chatgpt-vs-claude"
       permanent: boolean;   // true for 301
       reason?: string;      // e.g. "Consolidation into updated guide"
       retiredAt?: string;   // ISO datetime
     }
     ```
   - Export function `loadRedirects(filePath?: string): RedirectEntry[]`:
     * Reads `content/redirects.json`. If missing or corrupt, returns `[]`.
   - Export function `saveRedirects(entries: RedirectEntry[], filePath?: string): void`:
     * Formats and writes JSON atomically.
   - Export function `validateRedirectEntry(entry: RedirectEntry, existing: RedirectEntry[]): { valid: boolean; error?: string }`:
     * Enforces `entry.source.startsWith('/') && entry.destination.startsWith('/')`.
     * Fails if `entry.source === entry.destination` (self-referential loop).
     * Fails if `existing.some(e => e.source === entry.source)` (duplicate rule).
     * Fails if `existing.some(e => e.destination === entry.source && e.source === entry.destination)` (circular pair).
     * Warns/resolves if destination is already a source in `existing` (multi-hop chain).
   - Export function `formatForNextConfig(entries: RedirectEntry[]): Array<{ source: string; destination: string; permanent: boolean }>`:
     * Returns minimal payload required by Next.js `redirects()` configuration.
3. Update `next.config.mjs`:
   - Add safe JSON loading function `loadJsonRedirects()`:
     ```javascript
     import { readFileSync, existsSync } from 'node:fs';
     import { resolve } from 'node:path';

     function loadJsonRedirects() {
       try {
         const file = resolve('content/redirects.json');
         if (!existsSync(file)) return [];
         const data = JSON.parse(readFileSync(file, 'utf8'));
         if (!Array.isArray(data)) return [];
         return data.map(item => ({
           source: item.source,
           destination: item.destination,
           permanent: item.permanent ?? true,
         }));
       } catch (err) {
         console.warn('[next.config.mjs] Failed to load content/redirects.json:', err);
         return [];
       }
     }
     ```
   - In `nextConfig`, implement or extend `async redirects()` to return `loadJsonRedirects()`.
4. Create initial tests in `tests/redirects-consolidation.test.ts`:
   - Test JSON loading, saving, and empty-file fallback.
   - Test loop detection (A -> A, A -> B -> A).
   - Test chain detection (A -> B when B -> C already exists).
   - Test Next.js config formatting output.

<threat_model>
### Threat Ref T-06-05: Infinite Redirect Loops & Configuration Crashes
- **Threat:** Accidental entry of circular redirects (e.g., `/blog/a` -> `/blog/b` -> `/blog/a`) or malformed JSON in `content/redirects.json` causes browser infinite redirect loops or crashes Next.js during static site build.
- **Mitigation:** `lib/pipeline/redirects/registry.ts` validates all redirect entries against self-referential and circular paths before appending. In `next.config.mjs`, `loadJsonRedirects()` wraps parsing in a `try/catch` block and returns an empty array on any parsing anomaly, guaranteeing the Next.js compiler never crashes.
- **Verification:** Unit test in `tests/redirects-consolidation.test.ts` feeds circular rules (A->B, B->A) and malformed JSON into the loader, verifying that errors are caught and `loadJsonRedirects()` falls back gracefully.

### Threat Ref T-06-06: Orphaned MDX Residuals & Search Index Duplication
- **Threat:** A post is added to `content/redirects.json` but its `.mdx` file remains in `content/posts/`. `@content-collections` continues compiling the page, generating HTML and sitemap entries that fight the redirect and confuse search engines with soft-404s.
- **Mitigation:** The retirement workflow physically removes the file from `content/posts/` and relocates it to `content/quarantine/` while transitioning the keyword registry to `'quarantined'`. This ensures that Content Collections and `app/sitemap.ts` instantly stop serving the URL.
- **Verification:** Unit test in `tests/redirects-consolidation.test.ts` verifies that `content/posts/{slug}.mdx` ceases to exist on disk after retirement.
</threat_model>
