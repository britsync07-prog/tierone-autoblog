## Phase Boundary Context
Phase 6 delivers automated compounding and continuous optimization.
Plan 06-02 establishes the search-driven content refresh engine (GROW-02):
1. **Striking-Distance Detection**: Isolates queries ranking in positions 5.0–20.0 with $\ge 50$ impressions over 28 days where freshness and FAQ injection can produce immediate top-3 ranking gains.
2. **Content Decay Radar**: Analyzes historical traffic to identify mature articles ($\ge 90$ days old) experiencing a $\ge 25\%$ decrease in impressions or clicks.
3. **Structured Queue Management**: Persists actionable refresh tasks into `content/keywords/refresh-queue.json`.
4. **Autonomous Non-Destructive Refresh**: Bumps frontmatter `updatedAt`, synthesizes and injects striking-distance FAQ items while strictly respecting the 3–5 FAQ count constraint, and repairs dead outbound hyperlinks.

## Decisions Handled
- **D-04:** Striking-Distance & Content Decay Detection (pos 5.0–20.0 with $\ge 50$ impr; $\ge 90$d age with $\ge 25\%$ drop).
- **D-05:** Autonomous Refresh Execution & Queue (`content/keywords/refresh-queue.json`, `updatedAt` bump, FAQ injection under 3–5 limit, broken link repair).

   - Export type `RefreshItemType = 'striking-distance' | 'content-decay'`.
   - Export interface `RefreshQueueItem`:
     ```typescript
     export interface RefreshQueueItem {
       id: string; // e.g. "refresh-slug-YYYY-MM"
       slug: string;
       silo: string;
       type: RefreshItemType;
       priority: number; // 1-10 (10 highest)
       detectedAt: string;
       status: 'pending' | 'applied' | 'quarantined';
       appliedAt?: string;
       diagnostics: {
         currentImpressions: number;
         priorImpressions?: number;
         impressionsDropPct?: number;
         queries?: Array<{ query: string; position: number; impressions: number; clicks: number }>;
         brokenLinks?: string[];
       };
       suggestedActions: Array<{
         action: RefreshActionType;
         faqItem?: { q: string; a: string };
         targetDestination?: string;
         details?: string;
       }>;
     }
     ```
   - Export interface `RefreshQueueFile`: `{ version: 1; updatedAt: string; items: RefreshQueueItem[] }`.
2. Create `lib/pipeline/refresh/detect.ts`:
   - Function `detectStrikingDistance(analyticsRows: GscSearchRow[], existingPosts: Array<{ slug: string; silo: string }>): RefreshQueueItem[]`:
     * Filters rows where `position >= 5.0 && position <= 20.0 && impressions >= 50`.
     * Groups by page/slug.
     * Computes `opportunityScore = impressions * (21.0 - position)`.
     * Maps top queries to suggested FAQ additions or heading expansions.
     * Generates `RefreshQueueItem` with priority scaled by opportunity score (normalized 1–10).
   - Function `detectContentDecay(posts: Array<{ slug: string; silo: string; publishedAt: string }>, analyticsHistory: { current30d: Map<string, { impressions: number; clicks: number }>; prior30d: Map<string, { impressions: number; clicks: number }> }, now?: Date): RefreshQueueItem[]`:
     * Filters posts where age $\ge 90$ days (`(now.getTime() - publishedDate.getTime()) >= 90 * 86400000`).
     * Compares `prior30d` vs `current30d`: requires prior impressions $\ge 100$ (filters out low-volume noise).
     * Calculates percentage drops: `dropImpr = (prior - current) / prior`.
     * If `dropImpr >= 0.25` or `dropClicks >= 0.25`: creates a `content-decay` queue item suggesting date bump, content update, or link audit.
3. Create `lib/pipeline/refresh/queue.ts`:
   - Function `loadRefreshQueue(filePath?: string): RefreshQueueFile`:
     * Reads `content/keywords/refresh-queue.json`. If missing, returns empty queue `{ version: 1, updatedAt: new Date().toISOString(), items: [] }`.
   - Function `saveRefreshQueue(queue: RefreshQueueFile, filePath?: string): void`:
     * Formats and writes JSON atomically.
   - Function `upsertRefreshQueue(existing: RefreshQueueFile, newItems: RefreshQueueItem[]): RefreshQueueFile`:
     * Merges new items by deterministic `id`, preserving status of already `'applied'` or `'quarantined'` items.
4. Create initial `content/keywords/refresh-queue.json` containing `{ "version": 1, "updatedAt": "...", "items": [] }`.
5. Create `tests/refresh-decay.test.ts` verifying striking-distance detection math, content decay threshold checks, and queue upsert operations.

     * Locates MDX post file: `content/posts/${item.slug}.mdx`.

     * Applies `bump-date-modified`:
       - Sets frontmatter `updatedAt = new Date().toISOString()`.

       - **Boundary Guard**: `draftSchema` in `lib/pipeline/draft-schema.ts` strictly enforces `faq.min(3).max(5)`.

       - If current length is $\ge 5$, does NOT append a 6th item. Instead, replaces the lowest priority FAQ or leaves the existing 5 untouched and notes the replacement in diagnostics.

       - Scans markdown body for external `http(s)://` URLs.

<threat_model>
### Threat Ref T-06-03: False-Positive Content Decay Churn & Queue Pollution
- **Threat:** Natural seasonal fluctuation or noise in low-volume search queries causes the decay radar to continuously flag posts, generating unnecessary file mutations and confusing git history.
- **Mitigation:** The decay detector enforces strict entry criteria: minimum post age of 90 days, minimum baseline volume of 100 impressions in the prior 30-day period, and a relative drop threshold of $\ge 25\%$. Queue items carry unique deterministic IDs to prevent duplicate tasks from being created across consecutive runs.
- **Verification:** Unit test in `tests/refresh-decay.test.ts` verifies that posts with <100 prior impressions or <25% drop are ignored by the detector.

### Threat Ref T-06-04: Frontmatter Schema Violation via FAQ Overflow & Broken Build
- **Threat:** Automated FAQ injection appends a new question to a post that already has 5 FAQ entries, violating the Zod `draftSchema` constraint (`.max(5)`), causing `@content-collections` and Next.js builds to fail in production.
- **Mitigation:** The FAQ injector checks `frontmatter.faq.length` before mutation. If the post already has 5 FAQs, it replaces the lowest-value FAQ or skips injection entirely while logging a diagnostic note. The modified frontmatter is re-validated against `draftSchema` before writing to disk.
- **Verification:** Unit test in `tests/refresh-decay.test.ts` seeds a post with 5 FAQs, invokes the injector, and asserts that the resulting post contains exactly 5 FAQs and passes `draftSchema.parse()`.
</threat_model>
