```typescript
export interface ImageConcept { slot: 'hero' | 'in-article-1' | 'in-article-2'; concept: string; alt: string; }
export interface GeneratedAsset { slot: string; avifPath: string; webpPath: string; ogJpgPath?: string; width: number; height: number; }

export interface ImageProvider {
  name: 'openai' | 'fixture';
  /** Returns raw image bytes (PNG). Implementations must be offline-safe when fixture. */
  generate(concept: ImageConcept, slug: string): Promise<Buffer>;
}

export function createImageProvider(): ImageProvider;   // 'fixture' when PIPELINE_IMAGE_FIXTURE=1 else openai
export async function prepareAssets(slug: string, concepts: ImageConcept[], provider: ImageProvider): Promise<GeneratedAsset[]>;
```
- openai provider: `import OpenAI from 'openai'` images API, model from env OPENAI_IMAGE_MODEL (default 'gpt-image-1'), size '1536x1024', style guard: single flat editorial illustration, NO text/logos/faces in-prompt (Phase 3 consistency policy; brand-integration can come later).
- prepareAssets pipeline per concept:
  1. hero: sharp → cover-crop/resize to 1280x720 (16:9, D-13) → write public/images/{slug}/hero.avif (quality ~60) + hero.webp (quality ~75) ("post image" pair)
  2. og: from the SAME hero art → 1200x630 center-crop → og.avif + og.jpg (JPEG q80) — avif satisfies the AVIF/WebP letter of PIPE-05, jpg is the crawler-compat hedge (LinkedIn/iMessage AVIF gaps); both listed in metadata
  3. in-article-N: 1080 → 1080x608 (16:9) → in-article-N.avif + .webp (NO og pair, NO hero priority)
  4. sharp failure = throw (do not write partial files): build all encodes in memory per slot, then write all bytes for that slot atomically after every encode succeeded.
- All files under public/images/{slug}/ only (slug validation inherited from registry id). mkdir recursive, overwrite ok (idempotent regeneration).
