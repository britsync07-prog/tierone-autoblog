<plan_context>
## Phase Boundary Context
Phase 7 delivers daily tech and AI news ingestion and publishing.
Plan 07-04 delivers the Daily Autonomous Publisher & GitHub Actions Workflow (NEWS-04):
1. **Autonomous Publishing Runner**: `scripts/publish-daily-news.ts` provides the master CLI orchestrator for daily news releases.
2. **Idempotency & Rate Governor**: Checks if an article has already been published today in `content/posts/`, preventing duplicate runs unless `--force` is provided.
3. **End-to-End Orchestration**: Ingestion $\rightarrow$ 24h filter $\rightarrow$ Deduplication $\rightarrow$ Scoring $\rightarrow$ LLM synthesis $\rightarrow$ Frontmatter validation $\rightarrow$ MDX write $\rightarrow$ Ledger update $\rightarrow$ Dual-track indexing.
4. **Cloudflare Pages & Git Integration**: In CI, automatically commits the new post and updated covered ledger to `master`, immediately triggering Cloudflare Pages edge build and deployment.
5. **Scheduled Automation**: `.github/workflows/daily-news.yml` executes at 06:00 UTC every day, ensuring fresh content is indexed before Tier-1 morning search traffic peaks.
6. **Comprehensive Automated Verification**: Tests verify `--dry-run`, idempotency, ledger updates, and indexing dispatch mocking without modifying live production files.

## Decisions Handled
- **D-01 (Daily Publishing Schedule):** Fixed daily execution at 06:00 UTC (midnight CST / 02:00 EST) guarantees regular search engine discovery and freshness signals.
- **D-02 (Idempotent Daily Guard):** Single-post-per-day default prevents accidental runaway publishing while `--force` supports breaking news event spikes.
- **D-03 (Automated Git & CI Deployment):** Posts committed directly to Git trigger Cloudflare Pages deployments with zero manual touch.
</plan_context>

1. Create `scripts/publish-daily-news.ts`:
   - Parse CLI arguments using `process.argv`:
     * `--dry-run`: Boolean flag.
     * `--force`: Boolean flag.
     * `--feed=<source>`: String filter (`hn`, `google`, `techcrunch`, `verge`).
     * `--mock`: Boolean flag for offline testing.
   - Implement `checkAlreadyPublishedToday(postsDir?: string, now: Date = new Date()): { alreadyPublished: boolean; todaySlug?: string }`:
     * Inspects `content/posts/*.mdx`.
     * Parses frontmatter `publishedAt` and `silo`.
     * Returns true if any post with `silo === 'ai-news'` was published on today's UTC date (`YYYY-MM-DD`).
   - Implement `runDailyNewsPublisher(options?: { dryRun?: boolean; force?: boolean; feed?: string; mock?: boolean; postsDir?: string; ledgerPath?: string; now?: Date }): Promise<{ success: boolean; reason?: string; postPath?: string; slug?: string }>`:
     * Step 1: Idempotency check. If `checkAlreadyPublishedToday()` returns true and `!options?.force`, logs "News article already published today. Exiting cleanly (code 0)" and returns `{ success: true, reason: 'already_published' }`.
     * Step 2: Ingest and rank candidates via `aggregateDailyNews()`. If no fresh, uncovered candidates are found, logs "No uncovered news candidates found within 24h window. Exiting 0" and returns `{ success: true, reason: 'no_candidates' }`.
     * Step 3: Select top story (`candidate = result.selected`). Log story headline, source, and score.
     * Step 4: Synthesize article via `synthesizeNewsArticle(candidate, { mock: options?.mock })`.
     * Step 5: Assemble MDX and validate frontmatter via `assembleNewsPostMdx(synthesized, candidate.link)`.
     * Step 6: If `options?.dryRun` is active:
       - Log generated frontmatter and first 300 words of body.
       - Log "Dry-run complete. No files written, no indexers pinged."
       - Return `{ success: true, reason: 'dry_run', slug: synthesized.slug }`.
     * Step 7: Write MDX file to `content/posts/${synthesized.slug}.mdx`.
     * Step 8: Update `content/news/covered.json`:
       - Append new `CoveredEvent` with ID, title, normalizedTitle, sourceUrl, canonicalDomain, publishedDate, coveredAt, postSlug, and keywords.
       - Save ledger.
     * Step 9: Update `content/keywords/ai-news/registry.json`:
       - Append entry with stage `'published'`, `keyword: candidate.title`, `draft: { slug: synthesized.slug }`.
     * Step 10: Dispatch dual-track indexing:
       - Call `dispatchDualTrackIndexing({ url: `${SITE_URL}/blog/${synthesized.slug}`, sitemapUrl: `${SITE_URL}/sitemap.xml` })`.
       - Log indexing confirmation to `content/keywords/indexing-log.json`.
     * Step 11: Return `{ success: true, postPath: targetPath, slug: synthesized.slug }`.
   - Wrap top-level runner in `if (process.argv[1] && process.argv[1].endsWith('publish-daily-news.ts')) { runDailyNewsPublisher(...); }`.

2. Update `package.json`:
   - Add script `"news:publish": "tsx scripts/publish-daily-news.ts"`.
</action>

<threat_model>
### Threat Ref T-07-06: Autonomous Runaway Publishing, Race Conditions & Build Failures
- **Threat:** An unconstrained cron job could trigger multiple times within an hour or enter an infinite loop, publishing hundreds of low-quality posts, burning GitHub Actions minutes, overwhelming search engine crawlers, or causing Git push conflicts.
- **Mitigation:** The publisher enforces strict single-execution idempotency by checking `checkAlreadyPublishedToday()` before touching external services. The workflow uses `[skip ci]` in the commit message to prevent recursive GitHub Action runs. If an unexpected error occurs during synthesis or validation, the runner fails closed, writes no corrupt files, and exits cleanly without publishing broken posts.
- **Verification:** `tests/news-publish.test.ts` executes sequential publication attempts against temporary workspaces and verifies that the second run terminates immediately with code 0 and `already_published` status.
</threat_model>
